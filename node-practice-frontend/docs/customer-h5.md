# 客户端 H5 项目结构规划文档

## 1. 项目概述

本项目是基于 Vue 3 + TypeScript + Vite 构建的移动端 H5 应用，主要面向客户端用户，提供包括登录注册、产品浏览、订购、个人中心等功能。

## 2. 当前项目问题分析

通过对当前项目结构的分析，发现以下问题：

1. **文件夹结构不一致**：部分功能模块放在同一层级，部分功能又拆分较细
2. **命名不统一**：同时存在 `product` 和 `goods` 等类似功能的目录
3. **功能重叠**：部分视图和组件功能存在重叠，没有明确的职责划分
4. **通用组件混杂**：通用组件和业务组件混在一起
5. **缺少模块说明文档**：各模块功能缺乏明确的文档说明

## 4. 文件夹功能说明

### 4.1 API 层 (`api/`)

API 层负责所有与后端服务的通信，按功能模块进行拆分：

- **auth.ts**: 认证相关 API，包括登录、注册、找回密码等
- **product.ts**: 产品相关 API，包括产品列表、详情、推荐等
- **order.ts**: 订单相关 API，包括订单创建、查询、支付等
- **user.ts**: 用户相关 API，包括用户信息、设置等

### 4.2 组件 (`components/`)

组件目录分为三类：通用组件、业务组件和布局组件：

- **通用组件 (`common/`)**: 与业务无关的纯展示组件，如按钮、输入框等
- **业务组件 (`business/`)**: 与特定业务相关的组件，如产品卡片、订单项等
- **布局组件 (`layout/`)**: 页面布局相关组件，如页面容器、头部、底部等

### 4.3 视图 (`views/`)

视图目录按功能模块进行组织，每个模块可以进一步细分：

- **认证 (`auth/`)**: 登录、注册、找回密码等
- **首页 (`home/`)**: 首页相关页面
- **产品 (`product/`)**: 产品列表、详情、搜索等
- **解决方案 (`solution/`)**: 解决方案相关页面
- **购物车 (`cart/`)**: 购物车相关页面
- **订单 (`order/`)**: 订单列表、详情、支付等
- **用户中心 (`user/`)**: 个人资料、设置、反馈等

## 5. 命名规范

为保持项目一致性，建议遵循以下命名规范：

1. **文件夹名称**: 使用小写字母，多个单词用连字符连接 (kebab-case)，如 `product-detail`
2. **组件文件**: 使用 PascalCase 命名，如 `ProductCard.vue`
3. **工具函数文件**: 使用 camelCase 命名，如 `formatDate.ts`
4. **API 和 Store 模块**: 使用业务模块名称，如 `product.ts`, `user.ts`

## 6. 代码规范

1. **组件设计原则**: 
   - 组件应该是独立的、可复用的，并且职责单一
   - 使用 Props 进行数据传递，Events 进行事件通信
   - 使用 Composition API 组织代码逻辑

2. **状态管理原则**:
   - 全局状态和多组件共享状态放在 Pinia store 中
   - 组件内部状态使用 ref/reactive 管理
   - 避免状态的重复定义

3. **样式规范**:
   - 优先使用组件作用域样式 (scoped)
   - 全局样式和变量放在 assets/styles 中
   - 使用 CSS 变量实现主题定制

## 7. 迁移计划

建议分阶段进行项目结构调整：

1. **阶段一**: 创建新的文件夹结构，不更改现有代码
2. **阶段二**: 逐步将通用组件移至新的位置，并更新引用
3. **阶段三**: 按功能模块重构业务组件和视图
4. **阶段四**: 重构 API 和 Store 层
5. **阶段五**: 清理废弃的文件和代码

## 8. 性能优化建议

1. **路由懒加载**: 对所有路由使用懒加载，减少首屏加载时间
2. **组件按需引入**: 第三方组件库使用按需引入方式
3. **资源优化**: 图片资源使用适当的格式和大小，考虑使用 WebP 格式
4. **缓存策略**: 合理使用缓存，避免频繁请求相同的数据
5. **虚拟列表**: 对于长列表使用虚拟列表技术提高性能

## 9. 总结

通过优化项目结构，可以实现以下目标：

1. 提高代码的可维护性和可扩展性
2. 减少重复代码，提高组件复用率
3. 清晰的责任划分，便于团队协作
4. 优化构建输出，提高应用性能

后续建议定期对项目结构进行评审和优化，确保项目架构与业务发展保持一致。
